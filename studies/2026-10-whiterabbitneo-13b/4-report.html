WhiteRabbitNeo 13B for cybersecurity tasks on a Mac mini

Quality and speed of a security-tuned language model compared with 13 other local models. Measured with Ollama on an Apple Mac mini (Apple M6, 32 GB unified memory). 20 October 2026.

Summary. WhiteRabbitNeo 13B is a competent source of security facts, but on this evidence it is not the best choice. It ranks 9 of 14 models with a quality score of 0.76, against 0.94 for qwen3.8 27B. It fabricates answers to questions about things that do not exist (honesty score 0.33), takes 12.8 s per question on average (median of the other models: 5.4 s), and occupies 11.7 GB of memory. On the Mac mini it generates 18.4 tokens per second, which is fast enough for interactive use. The newer 7B and 8B models in the same family and DeepHat V1 7B generate about 1.7 times as fast in less than half the memory, with a similar quality score (DeepHat V1 7B: 0.80).

1. Test setup

  • Machine: Apple Mac mini (Apple M6, 12 CPU cores, 12 GPU cores, 32 GB unified memory), macOS 27.0.1, Ollama 0.40.5. All models ran fully on the GPU (Metal).
  • Model under study: WhiteRabbitNeo-13B-v1, GGUF Q4_K_M from TheBloke/WhiteRabbitNeo-13B-GGUF, 7.87 GB. Base: Llama 2, 13 billion parameters. The SHA-256 checksum matches Hugging Face.
  • Compared with: qwen3.8 27B, qwen2.5-coder 14B, qwen3 8B, phi4 14B, codestral 22B, qwen2.5-coder 32B, deepseek-r1 14B, DeepHat V1 7B, WhiteRabbitNeo (Llama 3) 8B, mistral-nemo 12B, gemma3 12B, WhiteRabbitNeo 2.5 (Qwen) 7B, dolphin-llama3 8B. All are Q4 quantisations run on the same machine with the same settings.
  • Settings: context window 8192 tokens; temperature 0.2 for quality and 0 for speed; Ollama defaults otherwise. WhiteRabbitNeo was prompted in its own template (SYSTEM / USER / ASSISTANT); a second run used its official Tree-of-Thoughts system prompt.

2. Quality: 22 security tasks

Each task is scored automatically on keywords that a good answer must contain (for SQL injection: the name of the vulnerability and the fix with parameterised queries). Scores run from 0 to 1. Results are the mean of 3 runs with different sampling seeds where available; the range is printed next to each bar.

Strengths and weaknesses of WhiteRabbitNeo 13B

  • Strong: Code writing, Log analysis. Its security knowledge (0.94) matches the best models: it knows nmap, hashcat, Kerberoasting and EternalBlue.
  • Weak: CTF decoding (0.22); Honesty (no fabrication) (0.33). In 4 of 6 attempts it invented a description of CVE-2099-99999 or of an nmap flag that does not exist, instead of saying it does not know it. For a team that relies on the output, this is the most dangerous failure mode.
  • Lowest-scoring tasks: Decode base64 (0.00); Decode ROT13 (0.00); Non-existent nmap flag (0.00).
  • Official prompt: the long Tree-of-Thoughts system prompt does not improve the model (0.73 versus 0.76) and makes answers longer.

Newer versions and DeepHat

The best of the newer models is DeepHat V1 7B with 0.80 (WhiteRabbitNeo 13B: 0.76). The newer models generate about 1.7x as fast and use less memory, but do not clearly beat the 13B on quality.

deepseek-r1 is a reasoning model: it always thinks at length before answering. It was therefore given a generous limit of 3,000 tokens per question instead of 260; with 260 tokens it scored 0.19 because the answer never appeared. Its time per question is correspondingly much higher (27 s).

Memory use (GB, lower is better; the machine has 32 GB)

  • A 256-token answer (about 190 words) takes 14 seconds. Reading a 3,256-token log takes 9 seconds before the first word appears.
  • In the quality test WhiteRabbitNeo needed 12.8 seconds per question on average, versus 5.5 s for qwen2.5-coder 14B: its answers are much longer.
  • Its memory use (11.7 GB at context 8192) is higher than that of comparable models (qwen2.5-coder 14B: 9.7 GB) because Llama 2 13B has no memory-efficient grouped-query attention (GQA). It grows quickly with longer contexts.
  • Loading takes 2.8 seconds; the model stays loaded as long as Ollama keeps it in memory.

4. Conclusions and recommendations

  • Use it when you want a model without refusals for pentest questions in a lab, where a person checks the answers.
  • Do not use it where a fabricated answer causes harm (CVE look-ups, unsupervised triage) or where speed matters.
  • If you want a model from the WhiteRabbitNeo line, prefer DeepHat V1 7B over the 13B: 0.80 versus 0.76, 32 versus 18 tokens per second and 4.5 versus 11.7 GB.
  • Best small model (up to 6 GB): qwen3 8B (0.85, 29 tok/s, 5.2 GB). Fastest overall: DeepHat V1 7B at 32 tokens per second.
  • Best balance of quality, speed and memory for a 32 GB machine: qwen2.5-coder 14B (0.85, 16.6 tok/s, 9.7 GB). Best quality overall: qwen3.8 27B (0.94) at 16.5 GB.
  • The model is based on Llama 2 from 2023 and does not know recent vulnerabilities or techniques. Use is subject to the Llama 2 licence plus a WhiteRabbitNeo extension with restrictions; read LICENSE.txt and USE_POLICY.md before serious use.

5. Limitations

  • Small sample: 22 tasks scored on keywords. No human read the answers, so a correct answer phrased differently can lose points.
  • English prompts only; no exploit development, no long agentic tasks, no comparison with models outside this list.
  • One machine and one quantisation (Q4_K_M or equivalent). Other quantisations or other Apple chips will give other speeds.
  • The seeds differ only in sampling (temperature 0.2); the questions are identical.

Appendix B. Reproducing the results

On a machine with Ollama and the scripts in the package (bench_cyber.py, model_bench.py, bench_perf.py, bench_stream.py):

ollama create wrn13b -f modelfiles/Modelfile.wrn13b
python3 model_bench.py --models wrn13b qwen2.5-coder:14b cyber (quality; set BENCH_SEED=1 for another seed)
python3 bench_perf.py wrn13b qwen2.5-coder:14b (speed and memory)
python3 bench_stream.py wrn13b qwen3:8b (records the answer timing for the speed demo)
